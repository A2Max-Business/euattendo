# MCP OAuth Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Conectar clientes MCP OAuth preservando a autenticação por token existente.
**Architecture:** OAuth nativo, credenciais em api_tokens; estado efêmero em Redis compartilhado, sem nova tabela.
**Tech Stack:** Next.js, TypeScript, Zod, Upstash Redis, Supabase.
**Spec:** docs/superpowers/specs/2026-10-23-mcp-oauth-design.md

## Global Constraints
- PKCE S256 e resource obrigatórios; redirect exato; sem segredo no log ou query.
- Papel admin, org ativa e MFA existentes; nunca emitir sob suporte.
- Sem refresh nesta versão; acesso 24h revogável na tela atual.

## Review Focus
- Duas abas trocando organização não podem autorizar outra empresa.
- Cookie Strict em navegação externa não pode interromper consentimento.
- Código reapresentado ou PKCE errado não emite outro token.
- Redis indisponível nunca permite estado local substituto.
- Token OAuth do MCP não pode ser reutilizado na API REST.
